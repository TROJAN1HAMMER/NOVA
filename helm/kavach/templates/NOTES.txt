⚠  secrets.existingSecret is unset, so this release generated its own Secret
   from values.yaml's `secrets:` block — the defaults there are placeholders
   ("change-me...") suitable only for a first try. Before running this
   against anything real, either override every secrets.* value with
   --set-string / a values file kept out of git, or (recommended) point
   secrets.existingSecret at a Secret your CI/CD or secrets manager
   (External Secrets Operator, Sealed Secrets, Vault, ...) already maintains.

   demo, not for anything you want to keep.

{{- if ne .Values.config.reportStorageBackend "s3" }}

⚠  storage.reports.emptyDir is true but config.reportStorageBackend is not
   "s3" — generated reports will be lost whenever a pod restarts, since
   nothing is uploading them anywhere durable. Set reportStorageBackend to
   "s3" (with the S3_*/secrets.s3* values pointed at a real bucket or
